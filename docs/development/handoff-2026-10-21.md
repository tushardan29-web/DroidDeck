## What we fixed/confirmed this session

### 1. Log-scope injection: colon syntax works (zero-build)
`gamescope.convars.<name>:call("debug")` (colon!) in `droiddeck-env` fires the convar callback →
`LogScope::SetPriority` → Debug lines in session.log. Dot-syntax `.value=` bypasses the callback;
dot-syntax `.call()` SEGVs (gamescope issue #2161). Env file (via
`/sdcard/Android/data/com.droiddeck.launcher/files/droiddeck-env`, read by SessionService.extraEnv() and appended to guest env):
```
gamescope_log_focus=("debug");gamescope.convars.log_focus:call("debug")
gamescope_log_xwm=("debug");gamescope.convars.log_xwm:call("debug")
gamescope_log_wlserver=("debug");gamescope.convars.log_wlserver:call("debug")
gamescope_log_xdg_backend=("debug");gamescope.convars.log_xdg_backend:call("debug")
gamescope_log_waitable=("debug");gamescope.convars.log_waitable:call("debug")
gamescope_log_vulkan=("debug");gamescope.convars.log_vulkan:call("debug")
gamescope_vblank_debug=true
BL_GAMESCOPE_ARGS=--debug-focus
```
Confirmed: 58 "Rerolling global focus..." lines, wlserver/xwm debug flowing, no lua errors.

## Root-cause findings: why gamescope never paints (issue #1)

Chain established this session (sessions 2026-10-21-12/13-steam, logs via guest `grep` on
`/data/user/0/com.droiddeck.launcher/files/logs/<id>/session.log`):

1. Steam **is alive and mapped**: X window 35651643 (0x220003B…) pid 29751, WM_NAME "Steam Big Picture Mode", WM_CLASS steamwebhelper, STEAM_GAME=769, WM_STATE Normal, STEAM_INPUT_FOCUS=1. X-side focus tracking works: `xwm: determine_and_apply_focus focus 10485762` then `35651643`.
2. Steam writes control atoms: `GAMESCOPECTRL_BASELAYER_APPID = 413091, 769`; `GAMESCOPE_FOCUSABLE_WINDOWS = 35651643, 769, 29751`; `GAMESCOPE_FOCUSABLE_APPS = 769`. `GAMESCOPE_FOCUSED_WINDOW/APP` stay empty.
3. `pick_primary_focus_and_override` (steamcompmgr.cpp:4309) finds the window via ctxFocusControlAppIDs, but **`window_has_commits(w)` is false** (steamcompmgr.cpp:4469-4474) → `out->focusWindow` never set → global focus stays null → `hasRepaint` never set → **no paint, no READY, no firstFrame**. 58 "Rerolling global focus..." with zero commits confirms.
4. `window_has_commits` = any `commit_queue[i]->done` (steamcompmgr.cpp:1881-1894). `done` is set at steamcompmgr.cpp:7884 when the commit's fence signals via `doneCommits`.
5. Fence path (steamcompmgr.cpp:8495-8526):
   - acquire-timeline eventfd → wait normally (broken on kbase? unknown).
   - **dmabuf path**: `wlr_buffer_get_dmabuf` succeeds → `fence = dup(dmabuf.fd[0])` → waits on the dma-buf sync fd. **kbase cannot export dma-buf fences (root device limitation; ZINK vkGetMemoryFdKHR storms ×304/400+ in log) → this fd likely never signals → commit sits undoned forever.**
   - no-dmabuf path: `memoryFence()` < 0 → our patch **0150** marks `bKnownReady=true` → immediate Signal(). 0150 only covers the *non*-dmabuf path.
6. ZINK storms come from guest GL clients (steam/steamwebhelper run GL via zink over panvk); gamescope's own Vulkan selects Mali-G77 fine. "Destroying swapchain"/"Shutdown" lines = steam's GL verification step failing and restarting.

**Fix candidate (needs a gamescope patch, ask user before building):** on Mali, treat a dmabuf-backed commit fence that cannot signal as ready: e.g. in the `wlr_buffer_get_dmabuf` branch, poll the fd with a short timeout (or env/`PANVK_KBASE_DRI3=0`-style convar) and fall back to `bKnownReady=true` on timeout; alternatively extend 0150 to the dmabuf branch when `GpuInfo.mali()`. Patch slot: `tools/gamescope/patches/0151-…`, build via `gh workflow run "Build gamescope (patched)" -R tushardan29-web/DroidDeck --ref main -f tag=gamescope-3.16.29-mali-04`, update `tools/gamescope/release.env`, rebuild APK.

Alternative/parallel lever: force steam's GL away from dmabuf export (guest env like `LIBGL_KOPPER_DRI2=true` already set; consider `zink.use_exclusive_full_screen=false`-style knobs or disabling DRI3 import for steamwebhelper only) — untested.

## Tooling cheat-sheet

```bash
export ADB_SERIAL=<new-port-after-redo>   # ask user; wireless debugging port changes
CTL="python3 /data/data/com.termux/files/home/projects/DroidDeck/tools/droiddeckctl"
$CTL state | grep -E '"id"|"phase"|"suspended"'   # parse; output has "Resolved ADB serial" line before JSON — pipe through grep/sed, not json.load on full stdout
$CTL start steam --wait --timeout 240     # READY timeout is EXPECTED (no paint yet); session keeps running
$CTL stop --timeout 90
$CTL focus                                # xprop-derived window dump
$CTL guest -- sh -c 'grep -m5 "Rerolling" /data/user/0/com.droiddeck.launcher/files/logs/<id>/session.log'
# binaries into guest: base64 via command arg → /root/… (noexec on /sdcard)
```

- Guest X: `DISPLAY=:0 xprop -root | grep -i gamescope` shows the atom table (GAMESCOPE_*, GAMESCOPECTRL_*). No xwininfo.
- Steam logs in guest: `/root/.local/share/Steam/logs/` (cef_log.txt, steamwebhelper.log — grep dmabuf/export failures).
- Env file: `adb shell "printf 'KEY=val\n' >> /sdcard/Android/data/com.droiddeck.launcher/files/droiddeck-env"` (extraEnv() filters lines with `=`, appended after base env → wins over same-name base keys only if later in list; note `guest.add` order: base first, extra after).
